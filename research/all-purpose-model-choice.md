# `all-purpose` model choice

**Decision (26 July 2026): keep `openai/gpt-5.6-sol` with `reasoningEffort: medium`.** Do not switch this agent to Terra merely to save money: with the intended ChatGPT Pro OAuth path, the available first-party evidence shows no incremental *API-token* price to the user, while Sol is the flagship and has the stronger published results on the relevant broad, coding, browsing, long-context, and research-adjacent evaluations. OpenAI presents medium as a balanced starting point; for this agent, it is a reasonable default to validate rather than a proven optimum. This is a recommendation for this user and agent, not a claim that Sol is always the best value.

## What the IDs and integration actually are

- `gpt-5.6-sol` and `gpt-5.6-terra` are **public OpenAI API model IDs**, not OpenCode aliases or undocumented names: OpenAI gives each a model page, calls Sol the frontier/flagship tier and Terra the lower-cost, balanced tier, and says `gpt-5.6` aliases Sol. [Sol model page](https://developers.openai.com/api/docs/models/gpt-5.6-sol) · [Terra model page](https://developers.openai.com/api/docs/models/gpt-5.6-terra) · [model guidance](https://developers.openai.com/api/docs/guides/latest-model)
- In OpenCode, `openai/<id>` is provider/model syntax, not part of the OpenAI slug. Its agent documentation says unknown agent-frontmatter options pass through to the provider and gives `reasoningEffort` as the OpenAI example. [OpenCode agents docs](https://opencode.ai/docs/agents/#additional)
- OpenCode officially offers a **ChatGPT Plus/Pro OAuth** connection. Its current source authenticates to `chatgpt.com/backend-api/codex/responses`, sends the selected model ID, reports zero token prices for OAuth-discovered models, and admits GPT-5.6 family IDs except bare `gpt-5.6`; it filters out Pro reasoning mode. Thus `openai/gpt-5.6-sol` and `openai/gpt-5.6-terra` are supported *candidate IDs* through this provider, but the server/account remains authoritative for actual availability. [provider docs](https://opencode.ai/docs/providers/#openai) · [pinned OAuth source](https://github.com/anomalyco/opencode/blob/7534d23551f665e65080809975b4ca5c7d63807b/packages/opencode/src/plugin/openai/codex.ts)
- OpenCode's OpenAI provider-options layer carries `reasoningEffort`, and its Responses encoder writes it as `reasoning.effort`; **medium propagates**. The OpenAI protocol utility excludes `max` from the accepted wire values even though OpenAI's API supports it, so do not select `max` for this agent without rechecking the installed OpenCode version. [provider-options source](https://github.com/anomalyco/opencode/blob/7534d23551f665e65080809975b4ca5c7d63807b/packages/llm/src/providers/openai-options.ts) · [protocol-options source](https://github.com/anomalyco/opencode/blob/7534d23551f665e65080809975b4ca5c7d63807b/packages/llm/src/protocols/utils/openai-options.ts) · [encoder source](https://github.com/anomalyco/opencode/blob/7534d23551f665e65080809975b4ca5c7d63807b/packages/llm/src/protocols/openai-responses.ts) · [OpenAI reasoning docs](https://developers.openai.com/api/docs/guides/reasoning)

## Cost, quota, latency, and quality are different questions

| Dimension | Evidence and implication here |
| --- | --- |
| **Marginal dollar cost under Pro OAuth** | Treat it as **$0 additional API-token billing**, not as “Sol is free”: OpenCode’s OAuth model records set input/output/cache prices to zero and route to the ChatGPT Codex backend, whereas OpenAI’s published $5/$30 (Sol) and $2.50/$15 (Terra) per million input/output prices are API pricing. The Pro subscription remains a fixed cost. [OpenCode source](https://github.com/anomalyco/opencode/blob/7534d23551f665e65080809975b4ca5c7d63807b/packages/opencode/src/plugin/openai/codex.ts) · [OpenAI pricing/model pages](https://developers.openai.com/api/docs/models/gpt-5.6-sol) |
| **Quota consumption** | Not established by public primary evidence. OpenAI says Pro has model-specific, plan-dependent allowances and temporary unavailability at exhaustion; it does **not** publish a Sol-versus-Terra Codex/OAuth debit rate or say that OpenCode usage shares a particular displayed ChatGPT allowance. The user's not having hit Pro limits therefore removes the immediate practical reason to trade quality for a presumed quota saving, but does not prove there is none. [Pro limits](https://help.openai.com/en/articles/9793128-about-chatgpt-pro-plans) · [GPT-5.6 availability/limits](https://help.openai.com/en/articles/20001354-gpt-56-in-chatgpt) |
| **Latency** | Both API cards label speed “Fast.” OpenAI positions Terra as a capability/speed/cost balance but publishes no apples-to-apples Sol-vs-Terra latency number for this OAuth/OpenCode path. Do not claim Terra is faster for this agent without measuring it. [Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol) · [Terra](https://developers.openai.com/api/docs/models/gpt-5.6-terra) |
| **Quality and task fit** | Sol is the flagship; Terra is explicitly the lower-cost balanced tier. OpenAI's release table favors Sol over Terra on Agents' Last Exam (52.7 vs 50.4), coding-agent index (80 vs 77.4), BrowseComp (90.4% vs 87.5%), 1M-token MRCR (73.8% vs 72.5%), and several science/cyber measures. Terra is close enough to be a credible fallback, not an equivalence claim. The table does not identify an identical medium-effort setting for every result, so it is directional—not proof of a per-prompt win. [OpenAI release and tables](https://openai.com/index/gpt-5-6/) |

Both models have the same published 1.05M-token context window and 128K maximum output, so context capacity does not favor Terra. [Sol model page](https://developers.openai.com/api/docs/models/gpt-5.6-sol) · [Terra model page](https://developers.openai.com/api/docs/models/gpt-5.6-terra)

## Reasoning setting and recommendation

Keep **Sol / medium / low text verbosity**. OpenAI calls medium the balanced starting point for quality, reliability, latency, and cost; it specifically lists research and agentic coding among medium use cases. Lower effort favors speed and lower token use, while high and above are for quality-first difficult work. This agent's normal job is short conversation with only occasional primary-source research, its prompt denies delegation, and the user has unused Pro headroom. Medium is therefore a reasonable starting setting, but its research quality and latency for this agent remain to be measured locally. [OpenAI reasoning guidance](https://developers.openai.com/api/docs/guides/reasoning) · [GPT-5.6 guidance](https://developers.openai.com/api/docs/guides/latest-model)

Do **not** use API `reasoning.mode: pro`: OpenAI says it adds model work, latency, and billed output tokens for hard quality-first tasks, and OpenCode's OAuth source filters models configured with that mode. That is also contrary to this agent's terse, non-delegating role. [OpenAI model guidance](https://developers.openai.com/api/docs/guides/latest-model#pro-mode) · [OpenCode source](https://github.com/anomalyco/opencode/blob/7534d23551f665e65080809975b4ca5c7d63807b/packages/opencode/src/plugin/openai/codex.ts)

**When to reconsider:** use Terra/medium only if direct observation shows Sol causes meaningful Pro allowance pressure or unacceptable latency; try Terra/low only for latency-sensitive chat after confirming its research/citation performance is acceptable. Compare matched representative tasks rather than assuming either setting offers better practical value.

## Resolved repository mismatch

The README previously assigned Terra to general conversation and called the Sol-backed `all-purpose` agent cost-efficient. That wording matched **API** token pricing but incorrectly implied those prices applied to this user's ChatGPT Pro OAuth path. The README now describes the actual model choice without making a cost claim about `all-purpose` or general conversation. Quota and latency still need local measurement.

## Remaining uncertainty and the local evidence that settles it

1. Public sources do not state the exact OAuth quota pool, debit formula, or whether Sol consumes more allowance than Terra. Run `opencode models` while authenticated (OpenCode's documented discovery path) to confirm both are exposed, then record a matched set of ordinary conversations and primary-source research tasks until the account's quota/reset UI provides an observable result. [OpenCode providers docs](https://opencode.ai/docs/providers/#openai)
2. Public sources do not provide OpenCode/Codex OAuth latency percentiles or a controlled Sol-medium vs Terra-medium research benchmark. Time matched prompts locally, score citation correctness/completeness and task success, and compare quota behavior—not only elapsed time or token counts.
3. This repository's README correctly warns that its isolated tests did not validate the machine's real provider binding. The installed OpenCode version and authenticated model list, rather than this note, decide whether the selected public slug is usable in a particular environment.
