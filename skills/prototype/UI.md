# UI prototype

Use a UI prototype when the unresolved question is visual structure, information hierarchy, or interaction flow.

- Prefer placing the experiment in realistic surrounding UI so density, navigation, and data constraints remain visible.
- Create genuinely different variants only when comparison will answer the question; two strong options can be better than a forced set of three.
- Reuse the project's styling and components where that improves fidelity, but keep mutations stubbed or disposable.
- Provide a simple switch, route, or set of URLs for comparison. Clearly prevent temporary controls and routes from shipping.
- Record the winning decisions, then delete the alternatives and rebuild or harden the selected behavior as normal production work.
